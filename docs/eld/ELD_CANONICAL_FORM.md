# LeaseOS ELD Canonical Form — hash version `eld-h1`

**Normative source:** the header of `shared/eld/eldEvent.ts`. This page restates it for implementers in
other languages and points at the proof: `shared/eld/vectors/eld-h1.vectors.json`, generated by an
independent Python implementation (`shared/eld/vectors/eld_h1_reference.py`) and pinned by
`server/_core/eldCanonicalVectors.test.ts`. An implementation that reproduces every vector's canonical
bytes, `payloadHash` and `eventHash` is interoperable.

## Why this exists

Checkpoint 1 defined `eld-h1` as "SHA-256 over `JSON.stringify` of an explicitly ordered object". That
made the protocol *whatever JavaScript does*: ES number formatting (`1e21`, `1e-7`, shortest
round-trip doubles), ES string escaping, ISO timestamp text from `Date.prototype.toISOString`, and
insertion-order keys. A Kotlin, Swift or C producer would have had to reproduce a JavaScript runtime
to sign a log. This checkpoint replaces that with rules a producer can implement from this page.

## The canonical bytes

The canonical bytes are the **UTF-8 encoding, without a byte-order mark**, of a JSON text produced under
these rules. The rules are a strict subset of RFC 8785 (JSON Canonicalization Scheme). A JCS library
may be used; none is needed.

| # | Rule |
|---|---|
| 1 | **Value kinds:** object, array, string, integer, `true`, `false`, `null`. Nothing else. Floating-point numbers do not exist in the canonical form. |
| 2 | **Object:** `{` members `}`. Members are `"key":value` joined by `,`. Members are ordered by key, ascending, comparing keys as sequences of Unicode code points (byte order for ASCII keys). No duplicate keys. Every key in this contract is ASCII. |
| 3 | **Array:** `[` elements joined by `,` `]`. Element order is significant and preserved. Arrays are never sorted. |
| 4 | **String:** `"` + escaped content + `"`. Escape U+0022 as `\"`, U+005C as `\\`, U+0008 `\b`, U+0009 `\t`, U+000A `\n`, U+000C `\f`, U+000D `\r`, and every other code point below U+0020 as `\u` + four **lowercase** hex digits. Every other code point, including U+007F, U+2028, U+2029 and all non-ASCII, is emitted as its UTF-8 bytes unescaped. Strings must be well-formed Unicode: an unpaired surrogate is a refusal. No Unicode normalization is applied. |
| 5 | **Integer:** `-?(0\|[1-9][0-9]*)`, magnitude ≤ 2^53 − 1 (9007199254740991). No `+`, no leading zeros, no fraction, no exponent. Negative zero is `0`. |
| 6 | **No whitespace** anywhere, no trailing newline. |
| 7 | **Absence = null.** Every participating field is present; an optional field the producer did not set is `null`. |
| 8 | **Timestamps are integers:** `eventAtMs` is milliseconds since 1970-01-01T00:00:00Z. The device clock's offset is a separate integer, `eventUtcOffsetMinutes`. No timestamp text exists in the canonical form. |
| 9 | **UUIDs** are the 36-character hyphenated form in lowercase hex. Producers must emit lowercase; the server lowercases before canonicalizing so a mixed-case reference cannot become a second identity. |
| 10 | **Hashes** are 64 lowercase hex characters of SHA-256. |
| 11 | **Enumerations** (`eventType`, `dutyStatus`, `recordOrigin`, `locationSource`) are their string values verbatim. |

## The hashes

```
payloadHash = SHA-256( canonical bytes of the participating object )
eventHash   = SHA-256( UTF-8("eld-h1") ‖ 0x0A ‖ UTF-8(previousEventHash or "") ‖ 0x0A ‖ UTF-8(payloadHash) )
```

`previousEventHash` is the device's claim: the `eventHash` of its own previous event (`deviceSequence − 1`),
or absent for the first event it ever recorded. The chain is **per device**. `hashVersion` is stored on
every ledger row and every conflict row; a later `eld-h2` can coexist.

## The participating object

Twenty-one keys. The encoder sorts them; this table is by meaning. "Device-authored" means the device
produced the value and is accountable for it; "resolved" means the server maps it to its own identity
after the hash is checked.

| Key | Kind | Category |
|---|---|---|
| `hashVersion` | string | protocol constant `"eld-h1"` |
| `deviceRef` | string | resolved server identity carried through a stable, device-visible identifier (minted at enrolment, known to the device, checked against the enrolled row) |
| `eventRef` | string | device-authored UUID v4 |
| `deviceSequence` | integer ≥ 0 | device-authored |
| `eventType` | string | device-authored enumeration |
| `eventCode` | string \| null | device-authored, optional |
| `dutyStatus` | string \| null | device-authored enumeration, only on `duty_status_change` |
| `recordOrigin` | string | device-authored: `automatic` or `driver` |
| `eventAtMs` | integer | device-authored device clock, ms since epoch, within 1000 … 2147483647000 (the storable range) |
| `eventUtcOffsetMinutes` | integer \| null | device-authored, −840 … 840 |
| `unitNumber` | string \| null | device-authored claim of a unit's number: a stable, device-visible identifier the server resolves to `units.id` and checks against the organization |
| `latitudeE7` | integer \| null | device-authored, degrees × 10^7, ±900000000 |
| `longitudeE7` | integer \| null | device-authored, degrees × 10^7, ±1800000000 |
| `locationAccuracyMm` | integer \| null | device-authored, millimetres |
| `locationSource` | string \| null | device-authored enumeration |
| `jurisdiction` | string \| null | device-authored claim, ≤ 8 chars |
| `odometerM` | integer \| null | device-authored, metres |
| `engineHoursMillis` | integer \| null | device-authored, thousandths of an hour |
| `vehicleSpeedKphMillis` | integer \| null | device-authored, thousandths of a km/h |
| `annotation` | string \| null | device-authored, ≤ 500 chars |
| `supersedesEventRef` | string \| null | device-authored UUID v4, only on `correction` |

**Excluded, and why:** `id`, `orgRef`, `operatorId`, `unitId`, `receivedAt`, `sourceKind`, `sourceRef`,
`submittedByUserId`, `createdAt` are server-assigned; a device cannot know them at creation time, so they
cannot be under a hash the device computes. This is the line between two facts: **the integrity of what
the device claimed** (the hashes) and **the server's determination of who owns the event** (tenant from
`fieldDevices.orgRef`, operator from the device's user, unit from ownership). A tenant identifier in the
hash material would not make the client's word about tenancy trusted, so none is there.

## Fixed scales

Checkpoint 1 accepted floating-point coordinates, odometer, engine hours and speed with no stated
precision. That was ambiguous for any producer and unstable across languages. The contract now fixes the
precision explicitly, in the field names: 10^-7 degrees (≈ 1.1 cm), 1 mm, 1 m, 0.001 h (3.6 s),
0.001 km/h. The ledger's `double` columns (`latitude`, `longitude`, `locationAccuracyM`, `odometerKm`,
`engineHours`, `vehicleSpeedKph`) are **derived** from the integers for querying; the canonical bytes
stored in `canonicalJson` are the record, and a reader needing the exact value reads them. No schema
change was needed.

## Reference implementations

- TypeScript: `canonicalEncode`, `canonicalEldEvent`, `canonicalEldEventJson` in `shared/eld/eldEvent.ts`
  (no dependencies; ~60 lines).
- Python: `shared/eld/vectors/eld_h1_reference.py` — `json.dumps(value, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`
  over an integer-only value, which is exactly rules 1–6.
- Any language: a JSON encoder with sorted keys, no whitespace, the escape set in rule 4 and raw UTF-8
  output. Kotlin/Java: `TreeMap` + a minimal writer. Swift: `JSONEncoder` with `.sortedKeys` and
  `.withoutEscapingSlashes` emits raw non-ASCII and the same escape set; verify against the vectors.

## Vectors

`shared/eld/vectors/eld-h1.vectors.json` — 19 event vectors and 8 value vectors: minimal, complete,
explicit nulls equal absence, empty string, Unicode (BMP and astral), quotation mark, backslash, control
characters and DEL, U+2028/U+2029 raw, negative and positive coordinates, coordinate bounds, timestamp and
range edges, predecessor hash, correction, uppercase UUID normalization, 2^53 − 1, another device; nested
unsorted object, arrays, empty containers, code-point key ordering, literals, integers, every escape,
empty string. Regenerate only with the Python script; never from the TypeScript code.
